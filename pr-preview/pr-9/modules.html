class litestar_events.plugin.EventsPlugin(config=None)[source]#

Bases: InitPluginProtocol, CLIPlugin

Install an emitter backend and add the litestar events commands.

Use the same plugin and config in the web app and the worker. The worker runs the same Litestar app through litestar events run, which always consumes only; set EventsConfig(role="producer") so the web process publishes only.

Plugin order matters for the request id: with request_id_header set, the middleware goes first in the app’s list when this plugin initializes, so list EventsPlugin last in plugins=[...] to keep it outermost.

config (EventsConfig | None)

from litestar.di import Provide
from litestar.plugins import InitPluginProtocol

Wire format and listener-argument binding shared by every backend.

The producer and the worker must agree on the bytes that travel through the broker. This module is that single definition: JSONCodec encodes emit(event_id, *args, **kwargs) into a versioned JSON envelope and decodes it again on the worker, optionally converting the decoded values into the types annotated on the listener’s parameters.

litestar_events.codec.WIRE_VERSION = 1#

Version stamped on every message ("v"). Messages without it are version 1 messages written before the field existed. The envelope fields added since ("cid", "h") are optional, so the version is unchanged.

class litestar_events.codec.JSONCodec(*, typed=True, type_encoders=None, type_decoders=None)[source]#

Bases: object

JSON envelope: v, cid, h, args and kwargs keys.

Encoding uses Litestar’s serializer, so datetime, UUID, Decimal, dataclasses and msgspec/Pydantic models are all supported on the producer.

Parameters:

  • typed¶ – when True (default), the worker converts each decoded argument to the type annotated on the listener’s parameter (order: Order, when: datetime) before calling it. Unannotated parameters, and listeners whose annotations cannot be resolved, get plain JSON values. When False, every listener gets plain JSON values, as in earlier releases.

  • type_encoders¶ – extra Litestar-style type encoders for encode.

  • type_decoders¶ – extra (predicate, decoder) pairs for typed decoding.

  • typed (bool)

  • type_encoders (dict[Any, Callable[[Any], Any]] | None)

  • type_decoders (Sequence[tuple[Callable[[Any], bool], Callable[[Any, Any], Any]]] | None)

A listener whose single parameter is a model (dataclass, msgspec Struct, Pydantic model or TypedDict) can receive the whole keyword payload: app.emit("order_created", id=1, total=9) populates order: Order. A parameter annotated EventContext is injected with the event’s id, headers and correlation id.

Event headers, correlation ids and the listener-side event context.

Every event carries a correlation id and optional string headers across the broker. Set them for the events emitted in a block with event_headers(); read them in a listener by annotating a parameter as EventContext or by calling current_event(). Events emitted from inside a listener inherit its correlation id, so one request can be traced across processes.

class litestar_events.middleware.RequestIdMiddleware(*, header='x-request-id', echo=True, exclude_path_pattern=None)[source]#

Bases: ASGIMiddleware

Use the request’s id as the correlation id of events emitted during it.

The id is read from header (x-request-id by default). A missing or unsafe value is replaced with a generated one. Events emitted while the request is handled carry the id, so a worker’s logs can be tied back to the request. With echo the id is also set on the response.

Routes can opt out with opt={"exclude_request_id": True} or by path through exclude_path_pattern.

Add it through EventsConfig(request_id_header=...), or register it yourself as ordinary Litestar middleware.

Parameters:
